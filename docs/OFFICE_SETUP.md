# Getting these fixes onto the office Windows machine

**The office machine is ahead of the laptop on data, and behind it on code.** So
this is a `git pull` plus a re-seed — not a data migration. Do not copy the
laptop's `vector-store.json` or `faq-cache.json` over; the office box already has
its own, built by the same `PIPELINE_VERSION = 11` pipeline.

Budget 10 minutes. Do it the night before if you can.

## 1. Pull

```powershell
cd <repo>
git pull origin main
```

## 2. ⚠️ Check `SARVAM_MODEL` — this is the one that silently ruins the demo

Sarvam **retired `sarvam-30b`**. It now returns HTTP 400 on every single call.
`llm.generate` catches that and falls back to `gemma2:2b`, a 2-billion-parameter
local model, so nothing looks broken — no error on screen, no failed request —
and the demo just answers in noticeably worse Hindi and Marathi. That is what was
happening on the laptop before today, undetected.

`backend/config.py` now defaults to `sarvam-105b`, but **`.env` overrides the
default**, so if the office `.env` pins the old model the pull changes nothing:

```powershell
findstr SARVAM_MODEL .env
```

- prints `SARVAM_MODEL=sarvam-105b` → good
- prints `SARVAM_MODEL=sarvam-30b` → **edit it to `sarvam-105b` now**
- prints nothing → also good, the new default applies

## 3. Re-seed the FAQ cache

`git pull` brings the seed *definitions*; it doesn't put them in the cache.

Clear first, because some existing auto-cached entries were generated by the
fallback model while `sarvam-30b` was failing:

```powershell
curl -s -X POST http://localhost:5050/admin/projects/default/cache/clear ^
  -H "X-Admin-Token: %ADMIN_TOKEN%"
```

Then seed. Both are needed — the first is the existing 20-fact set, the second
adds the admission-rounds question, which `seed_faq.py` doesn't cover and which
is the one that was answering inconsistently across languages:

```powershell
python tools\seed_faq.py

curl -s -X POST http://localhost:5050/admin/projects/default/cache/seed ^
  -H "X-Admin-Token: %ADMIN_TOKEN%" -H "Content-Type: application/json" ^
  --data-binary @tools/demo_seeds.json
```

(`seed_faq.py` now reads `ADMIN_TOKEN` from the environment instead of assuming
the default — it used to 401 *after* printing "80 entries", which read like
success.)

## 4. Restart and confirm

```powershell
python -u run_backend.py
```

Read the startup line. It must say:

```
Models  : online=Sarvam:sarvam-105b  offline=gemma2:2b
```

## 5. Verify

```powershell
python tools\test_matrix.py
```

Expect `RESULT: 32/32 passed`.

Then the real check — the same question in three languages, which must all answer
**four rounds**:

- `How many rounds are there in the admission process?`
- `प्रवेश प्रक्रिया में कितने राउंड होते हैं?`
- `प्रवेश प्रक्रियेत किती फेऱ्या असतात?`

If any gives a different number, step 3 didn't take.

## 6. Warm the cache

Ask each question in `docs/DEMO_SCRIPT.md` once, privately. Seeded questions are
already instant; the rest take 10–23s the first time and are instant after. Doing
this beforehand also means a wrong answer can't get auto-cached mid-demo.

## What if the office box is *not* actually ahead?

If `git log` there doesn't show the `glossary.py` / `seed_faq.py` work — i.e. that
came from somewhere else — then it has no prospectus indexed and you'll need the
data too. That's what `demo-bundle.zip` on the USB stick is for:

```powershell
python tools\demo_bundle.py unpack demo-bundle.zip --force
```

It carries `.env`, the prospectus, the embeddings and the warmed cache (~6.6 MB).
It contains live API keys — move it privately and delete it after. Only use it if
the office machine genuinely lacks the data; restoring it over a good index is a
downgrade.

## Voice

Indic voice needs the `admission-indic-tts` container. On the laptop it was being
OOM-killed (Docker capped at 4.1 GB; `indic-parler-tts` is 0.9B params in float32,
~3.6 GB of weights). Also note `TTS_TIMEOUT` is 600s because CPU inference
measured 166–252s for one sentence — that is not viable live. Check with:

```powershell
docker ps --filter name=admission-indic-tts
curl http://localhost:8001/health
```

If it isn't healthy, demo voice in **English only** — that uses the browser's own
speech synthesis and needs no container.
